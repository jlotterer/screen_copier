# T018: Settings, consent, resume dialogs

## Goal
When this task is done, `src/screen_copier/ui/settings_dialog.py` lets the user edit every setting and manage the API key (masked display, enter, test, clear, and a keyring-unavailable state), saving through T004, and `ui/dialogs.py` provides the one-time `ConsentDialog`, the `ResumeDialog` with its newer-version mode, and the shared error and confirmation helpers. T019 decides when each dialog appears.

## Acceptance criteria
- Given a stored key `sk-ant-xxxxabcd`, When the settings dialog opens, Then the key field shows `••••abcd` and no widget's text contains the full key.
- Given an injected fake client whose `messages.create` succeeds, When "Test" is pressed, Then the dialog shows "Key works"; Given the fake raises a 401 authentication error, Then it shows "Key rejected".
- Given `keyring_available()` returns false and no environment key, When the dialog opens, Then it shows guidance to set `ANTHROPIC_API_KEY` and the Save Key button is disabled.
- Given the key comes from `ANTHROPIC_API_KEY`, When the dialog opens, Then it says the key comes from the environment and the Clear button is disabled.
- Given a `ResumeDialog` for a session that raised `UnsupportedVersion`, When it opens, Then it explains the newer version and offers only Discard.
- Given a `ResumeDialog` for a resumable session with 5 frames and 112 lines, When it opens, Then it shows "Resume previous capture (5 frames, 112 lines)?" with Resume and Discard buttons.
- Given a `ConsentDialog` bound to a stub controller and settings, When the user accepts, Then `consent_acknowledged` is saved as true and `controller.acknowledge_consent()` is called once.
- Given the settings dialog, When the camera picker is populated, Then it lists the names from `list_cameras()` and preselects `camera_id`.
- Given changed values for exposure, capture thresholds, model, concurrency, line ending, sound and retention, When OK is pressed, Then `save_settings` is called with a `Settings` object carrying those values.
- Given the stub controller emits `auth_required`, When the dialog is shown in response, Then it opens with a message explaining that the key is missing or rejected.

## Notes for the worker
`SettingsDialog(controller, settings, *, client_factory, keyring_backend=None)`: camera picker from `list_cameras()`, exposure (auto toggle and value), the capture thresholds, model, `max_concurrent_requests`, line ending, sound, retention; an API key section with the masked display from `mask_key`, Enter (calls `set_api_key`), Test (a `messages.create` call with `max_tokens=1` and the text "ping" to the configured model through the injected client; success → "Key works", 401/403 → "Key rejected", connection error → "Could not reach the API"), Clear (`clear_api_key`), and the keyring-unavailable state with environment-variable guidance. Saves through `save_settings` and tells the controller the camera or exposure changed through `select_camera`. Expose a method to open the dialog with an explanation for `auth_required`; after a key change the caller resumes the queue. `dialogs.py`: `ConsentDialog` (a one-time notice that images go to Anthropic's API; acceptance sets `consent_acknowledged`, saves settings and calls `controller.acknowledge_consent()`), `ResumeDialog(session | None, unsupported: bool)` with Resume/Discard or Discard only, and helpers for the error dialog and the gap-save and edit-loss confirmations other views use. Never show more than the last 4 characters of the key anywhere. Tests use pytest-qt, a fake client and a fake keyring backend. T015, T016 and T017 run in parallel in other `ui/` files; touch only the files listed here.
