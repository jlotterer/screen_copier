# T015: Preview, quad handles, banner, stats

## Goal
When this task is done, the Capture-mode screen exists: `src/screen_copier/ui/preview_widget.py` paints the live preview with the detected screen outline, four draggable corner handles and Lock/Clear buttons; `ui/banner.py` shows the stack of live warnings with sounds; and `ui/capture_view.py` composes them with a stats bar and the empty and camera-error states. All of it talks only to the controller signals and slots of the CaptureController contract. T019 places the view in the main window.

## Acceptance criteria
- Given a `CaptureView` bound to a stub controller (a `QObject` with the controller's signals), When the stub emits `warning("gap", "msg", True)`, Then the banner shows an entry for `gap` with that message; When it emits `warning("gap", "msg", False)`, Then the entry is hidden.
- Given the preview with a frame shown, When the four corner handles are dragged to new positions and Lock is pressed, Then `controller.lock_region` is called once with a quad of 4 points matching the handle positions; When Clear is pressed, Then `lock_region(None)` is called.
- Given the stub emits `camera_error("unavailable", "msg")`, When the view updates, Then the error state is shown with the message and a button labelled "Open camera privacy settings" that opens `ms-settings:privacy-webcam`.
- Given the stub emits `document_changed(document, stats)` with `frames = 5`, `lines = 112`, `gaps = 1`, `issues = 2`, `input_tokens = 100`, `output_tokens = 20`, When the stats bar updates, Then it shows those six values.
- Given the stub emits `resolution(1920, 1080)`, When the stats bar updates, Then it shows `1920×1080`.
- Given `sound_enabled` is false and `QSoundEffect` is mocked, When a capture or a `gap` warning occurs, Then no sound is played; Given `sound_enabled` is true, When a `gap` warning is raised, Then the gap sound (not the capture sound) is played.
- Given the stub emits `trigger_state("SETTLING")`, When the preview updates, Then it shows the label "Settling…"; the other states map to "Moving…", "Waiting for focus" and "Captured".
- Given the stub emits `frame_added`, When the preview updates, Then a capture flash is shown and, with sound on, the capture sound is played.

## Notes for the worker
`PreviewWidget` paints `preview_frame(QImage, quad)` scaled to fit, draws the quad (a `(4, 2)` float32 array ordered TL, TR, BR, BL, see the Preprocess contract) in frame coordinates mapped to widget coordinates, and exposes 4 draggable corner handles plus Lock and Clear buttons calling `controller.lock_region(quad | None)`. It shows the trigger-state label and a short capture flash on `frame_added`. `Banner` keeps one entry per warning `kind`, shows, updates or hides on `warning(kind, message, active)`, has a dismiss button per entry, and plays the capture sound and a distinct gap sound through `QSoundEffect` with the two bundled WAV files when the `sound_enabled` setting is true; make the sound player injectable so tests mock it. `CaptureView` composes the preview, a stats bar (frames, lines, gaps, issues, tokens, resolution, Auto/Manual) and the banner, and renders empty and error states for `camera_error` (kinds `not_found`, `unavailable`, `disconnected`) with the privacy-settings button and a Retry/Reconnect button that calls `controller.select_camera`. Construct the view with the controller and read `sound_enabled` from the `Settings` object passed in. The two WAV files must be short, original and included as package data. Tests use pytest-qt with a stub controller; no real camera. T016, T017 and T018 run in parallel in other `ui/` files; touch only the files listed here.
