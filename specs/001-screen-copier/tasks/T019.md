# T019: Main window, modes, shortcuts, startup flow, E2E test

## Goal
When this task is done, `src/screen_copier/ui/main_window.py` assembles the app into one window with a toolbar, stacked Capture and Review views, the docked frame strip and every keyboard shortcut; `src/screen_copier/app.py` runs the startup flow (logging, settings, retention cleanup, resume discovery, controller and window, consent on first capture) and installs the global exception handler; and an end-to-end test proves the whole flow with the fake camera and fake recognizer.

## Acceptance criteria
- Given the app started with `SCREEN_COPIER_FAKE_CAMERA`, `SCREEN_COPIER_FAKE_RECOGNIZER` pointing at `tests/fixtures/recognizer/seq_basic/` and a temporary data dir, When the consent dialog is accepted, 5 frames are captured with Space, Tab switches to Review and Ctrl+S is pressed with the file dialog mocked to a temporary path, Then the written file equals `tests/fixtures/stitching/seq_basic/expected.txt`.
- Given Capture mode, When Tab is pressed, Then Review is shown; When Tab is pressed again, Then Capture is shown.
- Given Review mode with the editor focused, When Space is pressed, Then no frame is captured and a space is typed into the editor.
- Given edits made in Review, When the user switches to Capture and cancels the edit-loss confirmation, Then the edits are kept and the mode stays Review; When the user confirms, Then the mode is Capture.
- Given a session with 3 frames saved by a first app instance, When a second app instance starts on the same data dir, Then the resume dialog appears; When Resume is chosen, Then the frames and text are restored and any `queued` frame is recognized.
- Given an exception raised inside a slot, When it propagates to the exception hook, Then an error dialog is shown, the traceback is in the log file, and the session file still loads.
- Given the end-to-end run, When a `QTimer` probe measures event-loop latency throughout, Then no gap exceeds 100 ms (REQ-NFR-01).
- Given the main window, When every toolbar action is inspected, Then each has a keyboard shortcut or is reachable by Tab focus and activation from the keyboard (REQ-NFR-08).
- Given Ctrl+N is pressed with unsaved frames, When the confirmation is cancelled, Then the session is unchanged; When confirmed, Then `controller.new_session()` is called.
- Given startup with a `saved` session 8 days old and `session_retention_days = 7`, When the app starts, Then that session folder is deleted before the window shows.

## Notes for the worker
`MainWindow(controller, settings, store)`: toolbar with mode toggle, Auto toggle, Capture, Save and Settings; a `QStackedWidget` with `CaptureView` and `ReviewView`; `FrameStrip` in a bottom dock; the shortcuts from the UIStructure contract (Space capture, A toggle Auto, Tab switch mode, Ctrl+S save, Delete discard selected frame, Ctrl+N new session), with the capture-only shortcuts (Space, A, Delete) disabled while the `CodeEditor` has focus. Leaving Review after edits asks the edit-loss confirmation from `ui/dialogs.py` (REQ-REV-12). Ctrl+N confirms when the session has unsaved frames. `app.py` startup order: `setup_logging()`; `load_settings()`; `SessionStore(data_dir(), clock)` and `cleanup_saved(settings.session_retention_days)`; `find_unfinished()` → `ResumeDialog` (Discard calls `store.discard`; an `UnsupportedVersion` on load shows the discard-only mode; `CorruptSession` tells the user and starts fresh); create the controller (fake camera and fake recognizer when the environment variables are set, else `CameraWorker` and `ClaudeRecognizer` with `client_factory_for(get_api_key)`) and the window; show `ConsentDialog` on the controller's `consent_required`; open `SettingsDialog` with its explanation on `auth_required` and resume the queue after the key changes. Install `sys.excepthook` and Qt's message handler to log the traceback and show the error dialog; the session is already saved, so it continues. Keep `--version` working and leave the `--create-shortcut` branch for T020. The E2E test drives the real window with pytest-qt, `tmp_path` as `SCREEN_COPIER_DATA_DIR`, and mocks only `QFileDialog`.
