# T011: Atomic autosave, resume discovery, retention, migrations

## Goal
When this task is done, `src/screen_copier/session/store.py` provides `SessionStore`, which persists sessions atomically under `<data_dir>/sessions/<id>/`, writes each frame image before any session save, finds the newest unfinished session, discards and cleans up sessions, and prepares a session for resume; `session/migrations.py` holds the schema migration registry. A crash never loses a capture. T014 saves through it and T019 calls it at startup.

## Acceptance criteria
- Given a session with 3 frames, their results and an `edited_text`, When it is saved with `save_frame_image` for each frame and then `save`, and loaded again with `load`, Then the loaded session equals the saved one and the three frame JPEGs exist under `frames/`.
- Given `os.replace` patched to raise in the middle of `save`, When `save` is called on a session that was saved before, Then the previous `session.json` is still present and loadable.
- Given a `session.json` containing invalid JSON, When `load` is called, Then the file is renamed to `session.corrupt-<UTC timestamp>.json` and `CorruptSession` is raised.
- Given a `session.json` with `schema_version: 99`, When `load` is called, Then `UnsupportedVersion` is raised.
- Given a fake clock and `retention_days = 7`, When `cleanup_saved` runs over a `saved` session 8 days old, a `saved` session 6 days old and an unsaved session 30 days old, Then the 8-day-old session is deleted, the 6-day-old one is kept and the unsaved one is kept.
- Given a session with frames in states `recognizing`, `queued` and `recognized`, When `prepare_resume` runs, Then the `recognizing` frame becomes `queued` and the others are unchanged.
- Given one `saved` and two unsaved sessions, When `find_unfinished` runs, Then it returns the newest unsaved session.
- Given a stored session, When `discard(id)` runs, Then its folder no longer exists.
- Given the modules under `src/screen_copier/session/`, When their import statements are inspected, Then none imports PySide6.

## Notes for the worker
Follow the SessionStore contract for the layout and method names: `SessionStore(data_dir, clock)` with `create`, `save_frame_image`, `save`, `load`, `find_unfinished`, `discard`, `cleanup_saved` and `prepare_resume`, plus `CorruptSession`. Atomic save means writing `session.json.tmp` in the same folder, `fsync`, then `os.replace`; `atomic_write_text` in `config/paths.py` already does this for text. `save_frame_image` must write `frames/<seq>.jpg` before the session that references it is saved (REQ-NFR-07). `load` runs `migrate` first: `MIGRATIONS` is a `dict[int, Callable[[dict], dict]]` upgrading v → v+1, applied in sequence, after which the file is rewritten; a version above `SCHEMA_VERSION` raises `UnsupportedVersion` from `models.py`, and a session that is `saved` is never offered for resume. The clock returns a timezone-aware UTC datetime; never read real time. Use `tmp_path` as the data dir in tests. Design background: [architecture.md §10.2–10.4](../../../docs/architecture.md#102-state-ownership). Siblings T004 to T010 run in parallel in their own packages; stay inside `session/` and `tests/session/`. The owner reviews this PR because it defines the persisted format and its migrations.
