# T002: Pydantic data models + JSON round-trip

## Goal
When this task is done, `src/screen_copier/models.py` defines the pydantic v2 models that every other module exchanges (`Session`, `Frame`, `FrameQuality`, `Usage`, `FrameResult`, `RecognizedLine`, `Observation`, `DocLine`, `Segment`, `Gap`, `Document`, `StitchEvent`), the enums for frame status, capture mode, session state, DocLine flags, gap kind and event kind, the `SCHEMA_VERSION = 1` constant and the `UnsupportedVersion` exception, with JSON round-trip helpers using UTC datetimes. After this task `models.py` is the source of truth for the data contract that the Models contract mirrors.

## Acceptance criteria
- Given each entity (`Session`, `Frame`, `FrameQuality`, `Usage`, `FrameResult`, `RecognizedLine`, `Observation`, `DocLine`, `Segment`, `Gap`, `Document`, `StitchEvent`) with every field populated, When it is dumped with `model_dump_json()` and validated back with `model_validate_json()`, Then the result equals the original.
- Given each entity with every nullable field set to null, When it is dumped to JSON and validated back, Then the result equals the original and the null fields stay null.
- Given a sample tool input with the ReportTool shape, When `FrameResult.model_validate` is called, Then it is accepted; Given the same input without the `lines` key, Then validation fails.
- Given `Frame` data with `seq = 0`, When validated, Then a `ValidationError` is raised; Given `seq = 1`, Then it is accepted.
- Given `RecognizedLine` data with `line_number = 0`, When validated, Then a `ValidationError` is raised; Given `line_number = None` or `line_number = 1`, Then it is accepted.
- Given `Session` JSON with `schema_version: 2`, When validated, Then `UnsupportedVersion` is raised rather than a `ValidationError`.
- Given `src/screen_copier/models.py`, When its import statements are inspected, Then PySide6 is not imported.

## Notes for the worker
Use the Models contract as the field list and the ReportTool contract as the shape `FrameResult` must validate exactly, so it can parse Claude's `tool_use.input` directly: `FrameResult` and `RecognizedLine` use strict types and ignore unknown keys. All datetimes are timezone-aware, normalized to UTC and serialized with `Z`. `Session.frames` is validated as strictly increasing by `seq`, and `Frame.result` is non-null iff `status == recognized`. Expose `StitchEvent(kind, frame_seq)` with its kind enum. If any field name ends up differing from the Models contract, update [architecture.md §10.1](../../../docs/architecture.md#101-entities-modelspy-pydantic-v2--code) and the Models contract in the same PR; the code is the source of truth once it exists.
