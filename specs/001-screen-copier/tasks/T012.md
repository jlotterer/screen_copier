# T012: CameraWorker thread, enumeration, exposure, fake camera

## Goal
When this task is done, `src/screen_copier/camera/source.py` delivers camera frames off the GUI thread through `CameraWorker(QThread)`, together with quality metrics, auto-capture decisions from `CaptureTrigger`, resolution, exposure control and camera errors, and `list_cameras()` enumerates devices; `camera/fake.py` provides `FakeCameraSource` so tests and demos run without hardware. T014 drives the worker through an injected factory.

## Acceptance criteria
- Given `tests/fixtures/camera/basic/` with 3 PNG images and a worker built on `FakeCameraSource`, When the worker runs, Then `preview_frame` is emitted with each of the 3 images in turn (checked with pytest-qt `waitSignal`).
- Given a fake source that reports 1920×1080, When the worker opens it, Then `resolution` is emitted once with `(1920, 1080)`.
- Given a 30 fps fake source, When the worker runs for 3 s, Then at least 45 `preview_frame` signals are emitted.
- Given a fake source whose `read` fails 30 times in a row, When the worker runs, Then `camera_error("disconnected", …)` is emitted and the worker stops.
- Given a running worker in Manual mode, When `capture_now()` is called once, Then exactly one `capture_requested` is emitted, carrying the full-resolution frame and a `FrameQuality`.
- Given Auto mode and a fake image sequence that moves and then holds still and sharp, When the worker runs with a fake clock, Then exactly one `capture_requested` is emitted.
- Given a fake source that reports 640×480, When the worker opens it, Then `hint("low_resolution", True)` is emitted.
- Given `SCREEN_COPIER_FAKE_CAMERA` set to a folder, When the camera source is selected, Then `FakeCameraSource` is used instead of `cv2.VideoCapture`.
- Manual, device-only: a real webcam reaches ≥1080p and a ≥15 fps preview, and `list_cameras()` names match the devices (assumption A-01). Record the results in the PR.

## Notes for the worker
Implement the CameraWorker contract: `CameraInfo`, `list_cameras()` (names from `QtMultimedia.QMediaDevices.videoInputs()` matched by position to DirectShow indices 0..9, "Camera N" when unmatched), `CameraWorker(QThread)` with the listed signals and slots, and `FakeCameraSource` exposing the `cv2.VideoCapture` read interface (`isOpened`, `read`, `get`, `set`, `release`) so the worker uses either through an injected `capture_factory`. Open with `cv2.VideoCapture(index, cv2.CAP_DSHOW)` and walk the resolution ladder 3840×2160, 2560×1440, 1920×1080, 1280×720, accepting the first whose frame reads back at that size; below 1280×720 emit the `low_resolution` hint. Exposure uses `CAP_PROP_AUTO_EXPOSURE` (0.75 auto, 0.25 manual) and `CAP_PROP_EXPOSURE`; "driver settings" sets `CAP_PROP_SETTINGS = 1`. Per preview frame: `prep`, `diff` against the previous prepped frame, `sharpness`, and when Auto is on `CaptureTrigger.update(diff_prev, sharpness, diff_last_capture)`; the worker owns the last-capture reference frame used for `diff_last_capture`, and after a manual capture calls `trigger.notify_manual_capture()`. Forward the `never_settles` hint through `hint`. Entering Auto mode calls `trigger.reset()`. Error mapping: open fails with no devices → `not_found`; open fails but a device exists → `unavailable`; 30 consecutive failed reads → `disconnected` and stop. The fake source cycles a folder's images in sorted order at 30 fps holding each `hold_ms` (default 1000), or loops a video file, and reports its native size. Add the three PNGs under `tests/fixtures/camera/basic/`. Nothing on the GUI thread may block: all reads happen inside `run()`, and signals use queued connections. Clock and sleep are injectable. Background: [architecture.md §4](../../../docs/architecture.md#4-threading-model), [§5.1](../../../docs/architecture.md#51-camera-source), [decision 0001](../../../docs/decisions/0001-pyside6-desktop-app.md). T009 and T013 run in parallel; stay inside `camera/`, `tests/camera/` and `tests/fixtures/camera/`.
