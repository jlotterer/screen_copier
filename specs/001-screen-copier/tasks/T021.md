# T021: Benchmark script, real-hardware run, tune defaults

## Goal
When this task is done, `scripts/benchmark.py` measures a captured session against a ground-truth file and reports accuracy, cost and issue-flagging metrics; the owner has run it on real hardware following instructions the worker prepares; the default capture and image thresholds in `config/settings.py` are tuned from the results; `docs/benchmark.md` records whether REQ-NFR-06 is met; and the design assumptions in architecture.md §18 are marked confirmed or revised.

## Acceptance criteria
- Given a session directory whose rendered document is missing one known line compared with the ground truth, When the benchmark metrics run, Then `missing_lines` is 1.
- Given a rendered document with one duplicated line, When the metrics run, Then `duplicated_lines` is 1.
- Given a rendered document with one character error on one line, When the metrics run, Then `exact_match_percent` reflects one wrong line and the character error rate is greater than 0.
- Given a document where the wrong line carries an `uncertain` flag, When the metrics run, Then `flagged_error_share` is 1.0; Given the wrong line has no flag, Then it is 0.0.
- Given `scripts/benchmark.py <session_dir> <ground_truth_file> --output report.md`, When it runs on a fixture session built from `tests/fixtures/stitching/seq_basic/`, Then `report.md` is written with the missing, duplicated, exact-match, character-error, gap, issue, frame, token and estimated-cost figures.
- Given `docs/benchmark.md`, When it is read, Then it states for each hardware run (line numbers on, line numbers off, and a second camera or lighting condition if available) whether REQ-NFR-06 (0 missing, 0 duplicated, ≥99% exact lines) is met, and where it is not, proposes revised targets or follow-up work with a rationale.
- Given architecture.md §18, When it is read, Then each of A-01 to A-04 is marked confirmed or revised with the evidence.
- Given `config/settings.py` after tuning, When the Settings defaults are compared with architecture.md §8.1, Then they agree.

## Notes for the worker
The script loads a session with `SessionStore.load`, rebuilds the document with `stitch` over its recognized frames (or uses `edited_text` when asked), renders it, aligns it with the ground truth using `difflib`, and reports missing lines, duplicated lines, exact-match percentage, character error rate, gap and issue counts, frame count, tokens from `Session.usage` and an estimated cost from a per-token price table kept at the top of the script, plus the share of real errors that were flagged as issues (are mistakes highlighted?). Put the metric functions in the script so `tests/test_benchmark.py` can import them. Hardware runs are the owner's: write step-by-step instructions into `docs/benchmark.md` for copying a 300-line Python file from a real monitor with (a) line numbers on, (b) line numbers off, and (c) a second camera or lighting condition if available, and leave clearly labelled result tables for them to fill; the PR then waits for those results. Tune `stable_duration_ms`, `stability_threshold`, `motion_threshold`, `sharpness_threshold` and `max_image_edge_px` from the results and change only the default values in `Settings` and the §8.1 table. The assumptions to resolve: A-01 QMediaDevices order matches DirectShow indices (wrong → wrong camera names; the "Camera N" fallback exists); A-02 the default capture thresholds suit a typical 1080p webcam (wrong → auto-capture too eager or never fires); A-03 a 1568 px long edge is enough for code at ≥14 px (wrong → raise `max_image_edge_px`); A-04 Claude reliably fills the tool schema including the edge flags (wrong → worse stitching; the Malformed retry mitigates).
