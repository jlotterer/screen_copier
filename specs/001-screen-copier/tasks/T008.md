# T008: Overlap mode, segments, gaps, voting, events

## Goal
When this task is done, `src/screen_copier/stitching/` holds the pure stitcher: `normalize.py` (line normalization and matching), `overlap.py` (candidate offsets, validation, best choice, ambiguity), `resolve.py` (observation voting and conflict flags) and `stitcher.py` (`Stitcher`, segments, gaps, bridging, rendering, events, `issue_count`), and every T003 fixture with `uses_line_numbers: false` passes both incrementally and in batch. It leaves a clear extension point for line-number mode, which T009 fills.

## Acceptance criteria
- Given every fixture in `tests/fixtures/stitching/` with `uses_line_numbers: false`, When its frames are added one at a time with `Stitcher.add`, Then `render()` equals `expected.txt` and the events, conflicts and flags equal `meta.json`.
- Given the same fixtures, When stitched in one call to `stitch(results, settings)`, Then the document and events equal the incremental result (REQ-STI-01).
- Given fixtures with `uses_line_numbers: true`, When the fixture test runs, Then they are marked `xfail` with the reason naming T009, not deleted or skipped silently.
- Given the inputs `"  a   b "` and `"a b"`, When `normalize` and `lines_match` run, Then `normalize` gives `a b` and `lines_match` is true; Given two blank lines, Then they match; Given lines whose similarity ratio is below `line_similarity`, Then they do not match.
- Given a line with fewer than 3 non-space characters after normalization (such as `}`), When `is_distinctive` runs, Then it is false; Given `});`, Then it is true.
- Given observations exercising each step of the resolution rule (certain over uncertain, strict majority of ≥3, latest wins, conflict with alternatives ordered by frequency then recency), When `resolve` runs, Then each step's test gives the specified text, flags and alternatives.
- Given frames 1–3 where frame 2 is discarded, When the remaining frames are re-stitched in batch, Then the document equals one built from frames 1 and 3 only.
- Given a frame with a `cut_off_right` line, When added, Then the DocLine's `Observation` has `cut_off_right = True`, the DocLine has the `cut_off` flag, and one `cut_off` event is emitted for that frame.
- Given a frame that shares no lines with the document, When added, Then a `Gap` with `kind = overlap` and the correct `before_segment` index is in `Document.gaps` and a `gap_detected` event is emitted.
- Given a bridge frame that merges two segments, and separately a discard followed by re-stitch, When the document is read, Then `Document.gaps` stays consistent with `segments`.
- Given a 2,000-line document, When one 60-line frame is added 5 times, Then the median duration is ≤200 ms; the test is marked `@pytest.mark.perf`.
- Given the modules under `src/screen_copier/stitching/`, When their import statements are inspected, Then none imports PySide6.

## Notes for the worker
Pre-filter: drop `partial` lines before anything else. Matching: `normalize` strips and collapses whitespace runs; two lines match when both are blank or `SequenceMatcher(None, normalize(a), normalize(b)).ratio() ≥ line_similarity`; a line is distinctive when its normalized text has ≥3 non-space characters. Overlap mode: compare the frame lines F with each segment S at every offset `o` (negative or past the end allowed) aligning `F[i]` with `S[o+i]`; a candidate is valid when the overlap has ≥ `min_overlap_lines` matching distinctive lines, ≥90% of overlapped lines match (fixed constant `MIN_MATCH_PERCENT = 90`), and the shape is a tail extension, head extension or containment (a frame covering a whole segment and extending past both ends is excluded). Score = matching lines; the best candidate across all segments wins; a second valid candidate with the same score at a different segment or offset makes the frame ambiguous: emit `ambiguous_overlap` and treat it as unplaced. Applying: overlapping lines add observations, the rest are appended or prepended. The first frame starts segment 0 with no event. An unplaced frame becomes a new segment inserted right after the segment that received the previous frame, with `gap_detected`. Bridging: after applying, test the modified segment against its neighbours with the same validity rule, treating the neighbour as the frame; merge and emit `gap_closed` when valid and not ambiguous, repeating until no neighbour fits; unplaced frames are not bridge-tested. Resolution per DocLine: group observations by exact text; if any is certain, drop the uncertain ones; with ≥3 remaining and a strict majority, use it; otherwise use the latest `frame_seq`; more than one distinct text remaining sets `conflict` and `alternatives` by frequency then recency; `uncertain` is set when the chosen observation is uncertain; `cut_off` when any observation had `cut_off_right`. Every offset with a non-empty overlap is scored because ambiguity detection needs all valid candidates; stop an offset at the first mismatch that breaks the 90% rule and cache normalized matches. Leave `Stitcher.uses_line_numbers(result, lines)` returning `False` and `_add_numbered` as the hook T009 fills, so numbered frames go through overlap mode until then. Read `tests/fixtures/stitching/README.md` first; the fixture folder format is in the Stitcher contract.
