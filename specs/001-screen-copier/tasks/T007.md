# T007: Prompt, tool schema, Claude recognizer, fake recognizer

## Goal
When this task is done, `src/screen_copier/recognition/` holds the `Recognizer` protocol and its outcome types (`base.py`), the system prompt and strict `REPORT_TOOL` schema (`prompt.py`), `ClaudeRecognizer` that sends one JPEG to Claude with an injected client and returns a typed outcome (`claude.py`), and `FakeRecognizer` that replays `<seq>.json` files for tests and demos (`fake.py`). T013 builds the queue on top of it; T014 injects either recognizer.

## Acceptance criteria
- Given a `ClaudeRecognizer` with a fake client and default settings, When `recognize` is called, Then the request uses model `claude-sonnet-5-5`, has no sampling parameters, `tool_choice` `{"type": "auto"}`, one `strict` tool named `report_transcription`, one `base64` `image/jpeg` content block, and the client was built with `max_retries=0`.
- Given `SYSTEM_PROMPT`, When it is read, Then it contains an instruction for each REQ-OCR-02 item: exact text with no corrections, indentation as spaces, line numbers reported separately from text, ignore surrounding UI, `partial`, `cut_off_right`, `uncertain` with a note, and word wrap.
- Given each row of the SDK outcome table in the Recognizer contract, When the fake client raises that SDK exception or returns that response, Then `recognize` returns the mapped outcome type.
- Given a response without a `tool_use` block, or one whose `input` fails `FrameResult` validation, When `recognize` is called, Then the outcome is `Malformed`.
- Given `FakeRecognizer("tests/fixtures/recognizer/seq_basic")`, When `recognize(b"", frame_seq=1)` is called, Then it returns `Ok` whose result equals `1.json`.
- Given the recognition package, When its source is scanned, Then the only network client constructed is `anthropic.Anthropic`, with `base_url` pinned to `https://api.anthropic.com`.

## Notes for the worker
`base.py` is the Recognizer contract verbatim: frozen dataclasses `Ok`, `Retryable`, `AuthError`, `BadRequest`, `Malformed` and the `Recognizer` protocol; a recognizer never retries and never raises for API or response problems. `prompt.py` exports `SYSTEM_PROMPT` and `REPORT_TOOL` exactly as the ReportTool contract shows. `claude.py`: `ClaudeRecognizer(client_factory, settings)` calls the factory and reads `settings.model` on every request, builds the request from the ReportTool contract, maps errors with the table in the Recognizer contract, parses `tool_use.input` into `FrameResult` and returns `Usage`; `client_factory_for(key_provider)` reuses one client until the key changes and raises `MissingApiKeyError` when none is set, which maps to `AuthError`. `fake.py`: `FakeRecognizer(directory, *, delay_s=0.0, sleep=time.sleep)` returns `Ok(FrameResult from <seq>.json)` or `Malformed` when the file is missing; the delay is for UI demos. Before writing API code, check the current `anthropic` SDK for `messages.create`, tool use and error classes. [Decision 0006](../../../docs/decisions/0006-strict-tool-auto-choice.md) explains why `tool_choice` is `auto` and there is no `temperature`: Sonnet 5.5 rejects a forced tool choice, and API version 2026-10-21 has no sampling parameters. [Decision 0002](../../../docs/decisions/0002-claude-vision-for-recognition.md) is why there is no local OCR. Tests never hit the network: inject a fake client. Background: [architecture.md §7](../../../docs/architecture.md#7-recognition).
