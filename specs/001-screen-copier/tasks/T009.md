# T009: Line-number mode, numbered gaps, soft wrap

## Goal
When this task is done, `src/screen_copier/stitching/linenum.py` places lines by the editor line numbers Claude reports, attaches soft-wrap continuation lines, computes numbered gaps (including missing lines at the top of the file) and emits `word_wrap` events, and it is wired into `Stitcher` through the `uses_line_numbers` / `_add_numbered` hook that T008 left. The four line-number fixtures from T003 pass and lose their `xfail` marks, while every overlap-mode fixture keeps passing.

## Acceptance criteria
- Given the fixtures `seq_linenums_gap`, `seq_linenums_start_missing`, `seq_soft_wrap` and `seq_mixed_numbering`, When their frames are added one at a time with `Stitcher.add`, Then `render()` equals `expected.txt` and the events, conflicts and flags equal `meta.json`.
- Given the same four fixtures, When stitched in one call to `stitch(results, settings)`, Then the document and events equal the incremental result.
- Given `tests/stitching/test_fixtures.py`, When it is read, Then no fixture is marked `xfail` any more.
- Given every fixture with `uses_line_numbers: false`, When the fixture tests run, Then they still pass unchanged.
- Given a frame with `has_line_numbers = true` and only one non-partial line carrying a `line_number`, When `uses_line_numbers(result, lines)` is called, Then it returns `False` and the frame is placed by overlap mode.
- Given a frame with `has_line_numbers = true` and at least two numbered non-partial lines, When `uses_line_numbers(result, lines)` is called, Then it returns `True`.
- Given a numbered frame with `word_wrap_detected = true`, When added, Then exactly one `word_wrap` event with that frame's seq is emitted.
- Given numbered frames covering lines 1–40 and 48–90, When added, Then `Document.gaps` contains one `Gap` with `kind = line_numbers` and `description = "lines 41–47 missing"` and the render shows the gap marker between line 40 and line 48.
- Given a first numbered frame whose lowest number is 5, When added, Then `Document.gaps` contains a `Gap` with `description = "lines 1–4 missing"` rendered before the first line.
- Given a numbered frame with a non-partial line whose `line_number` is null between numbered lines 19 and 20, When added, Then the line becomes its own DocLine right after line 19 with the `soft_wrap` flag and one `word_wrap` event is emitted.
- Given `src/screen_copier/stitching/linenum.py`, When its import statements are inspected, Then PySide6 is not imported.

## Notes for the worker
Start from the hook in `stitcher.py`: `Stitcher.uses_line_numbers(result, lines)` currently returns `False` and `_add_numbered(seq, result, lines, kinds)` raises `NotImplementedError`; `lines` is the frame after the partial-line pre-filter and `kinds` collects the event kinds for this frame (at most one per kind). Put the algorithm in `linenum.py` and keep the edits to `stitcher.py` minimal: the hook, the call into `linenum.py`, and whatever the document builder needs to render numbered segments and `line_numbers` gaps. The rules: line-number mode applies to a frame with `has_line_numbers = true` and ≥2 non-partial lines with a `line_number`. Each numbered line is an observation for document line `n`; keep line-number segments as a map from `n` to DocLine; contiguous runs of numbers form segments ordered by `n`, with `Segment.first_line_number` set. A non-partial line with `line_number = null` inside a numbered frame is attached immediately after the preceding numbered line as a DocLine with the `soft_wrap` flag (keyed `n + 0.1`, `n + 0.2`, …) and emits `word_wrap`; `word_wrap_detected = true` also emits `word_wrap` (still one event per frame). Every missing range between the minimum and maximum numbers becomes a `Gap` of kind `line_numbers` described as `lines X–Y missing` (en dash); a minimum above 1 adds `lines 1–(min−1) missing` at the top. A frame without numbers in a numbered document (`seq_mixed_numbering`) goes through overlap mode against the rendered numbered segments and its lines inherit numbers from the alignment, so a later numbered frame lines up with them without a gap or conflict. Observations on the same numbered line still resolve through `resolve.py`. Remove the `xfail` mark in `tests/stitching/test_fixtures.py` (the `uses_line_numbers` branch around line 50) rather than loosening any assertion. Fixture details are in `tests/fixtures/stitching/README.md`; the design is in [architecture.md §9.3](../../../docs/architecture.md#93-line-number-mode-stitchinglinenumpy). T012 and T013 run in parallel in other packages; stay inside `stitching/` and `tests/stitching/`.
