# T010: Language vote, syntax check, file writer

## Goal
When this task is done, `src/screen_copier/output/` provides the pure logic behind saving: `language.py` normalizes and votes on the language guesses and maps a language to a file extension, `syntax.py` checks Python, JSON, YAML, TOML and XML text and reports issues with correct line numbers despite gap markers, and `writer.py` renders the final bytes, builds the default filename and writes the file atomically with a typed `SaveError`. T017 calls all of it from the review view.

## Acceptance criteria
- Given the guesses `["python", "python", "text"]`, When `vote_language` runs, Then it returns `python`; Given `[]`, Then it returns `unknown`.
- Given the guesses `["json", "python"]` (a tie), When `vote_language` runs, Then it returns `python`, the most recent.
- Given the guesses `py`, `js`, `ts`, `c#`, `cs`, `c++`, `yml`, `bash`, `sh`, `ps1` and `plaintext`, When `normalize_language` runs, Then they map to `python`, `javascript`, `typescript`, `csharp`, `csharp`, `cpp`, `yaml`, `shell`, `shell`, `powershell` and `text`; an unmapped guess maps to `unknown`.
- Given Python text with a missing colon on line 12, When `check(text, "python")` runs, Then it returns one issue whose `line` is 12.
- Given valid JSON, YAML, TOML and XML text, When `check` runs for each language, Then it returns `[]`.
- Given the language `rust`, When `check` runs, Then it returns `None`.
- Given Python text with a gap marker line at line 3 and a syntax error at line 12, When `check` runs, Then the issue's `line` is still 12.
- Given the lines `a  ` (two trailing spaces) and `b` with the line ending `crlf`, When `render_for_save` runs, Then the bytes are exactly `b"a\r\nb\r\n"`.
- Given text ending in three blank lines, When `render_for_save` runs, Then the trailing blank lines are dropped and the output ends with exactly one line ending.
- Given any text, When `render_for_save` runs, Then the output starts with no BOM and is valid UTF-8.
- Given text containing a gap marker line, When `render_for_save` runs, Then the marker appears verbatim in the output.
- Given the language `python` and a fixed datetime, When `default_filename` runs, Then the result matches `capture-\d{8}-\d{6}\.py`.
- Given a destination path whose directory denies write permission, When the file is written, Then `SaveError` is raised carrying the OS message.
- Given the modules under `src/screen_copier/output/`, When their import statements are inspected, Then none imports PySide6.

## Notes for the worker
Implement exactly the names in the Output contract: `normalize_language`, `vote_language` (capture order in, ties to the most recent), `extension_for`, `SyntaxIssue`, `check`, `SaveError`, `render_for_save`, `default_filename` and `write_file`. The checkers are `ast.parse`, `json.loads`, `yaml.safe_load`, `tomllib.loads` and `xml.etree.ElementTree.fromstring`; map each library's error to `SyntaxIssue(line, column, message)` and return `None` for a language without a checker. Replace gap marker lines (the `GAP_MARKER` format from the Stitcher contract, importable from `stitching/stitcher.py`) with blank lines before parsing so line numbers hold. `render_for_save` takes the `LineEnding` enum from `config/settings.py`; the steps are rstrip each line, drop trailing blank lines, join with `\n` or `\r\n`, add exactly one final line ending, encode UTF-8 without a BOM. `default_filename` uses local time from the `now` argument, never the real clock. Writing is atomic (temp file in the same directory, then `os.replace`). Design background: [architecture.md §13](../../../docs/architecture.md#13-output). Siblings T004 to T011 run in parallel in their own packages; stay inside `output/` and `tests/output/`.
