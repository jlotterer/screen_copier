# T017: Editor, issue highlights/nav, syntax panel, save flow

## Goal
When this task is done, the Review-mode screen exists: `src/screen_copier/ui/code_editor.py` is a `QPlainTextEdit` with a gutter for line numbers and issue icons, issue highlights and tooltips; `ui/review_view.py` puts the source frames for the current line on the left, the editor on the right, an issue counter with keyboard navigation, a conflict picker, a language combo, a syntax panel and the Save flow built on T010's output module. Edits go to `controller.set_edited_text`. T019 places the view in the main window.

## Acceptance criteria
- Given a `ReviewView` showing a constructed `Document` with 2 `uncertain` lines and 1 gap, When it renders, Then the issue counter shows "3 issues"; When F8 is pressed three times, Then the cursor visits the two lines and the gap marker in document order; When one uncertain line is edited, Then the counter shows "2 issues" and that line's highlight is gone.
- Given a document where line 50 has observations from frames 4 and 5, When the cursor is placed on line 50, Then the left panel shows frames 4 and 5 and no others.
- Given a `conflict` line with alternatives `["a", "b"]`, When the conflict picker is opened and "a" is chosen, Then the line's text is "a" and its highlight is cleared.
- Given Python text with a missing colon on line 12, When the syntax check runs, Then the syntax panel lists line 12, clicking it moves the cursor to line 12, and the Save button stays enabled.
- Given the document has 1 gap, When Save is pressed, Then a confirmation names the gap count; When the confirmation is cancelled, Then nothing is written (QFileDialog and QMessageBox are mocked); When it is confirmed, Then the file dialog opens with the default name from `default_filename` and the file written contains the gap marker.
- Given every issue type (`uncertain`, `conflict`, `cut_off`, `soft_wrap`, gap), When the editor renders a line with it, Then the gutter shows an icon with a distinct shape per type, the line has a background color, and hovering shows a tooltip with the reason.
- Given frames mostly guessed as Python, When the view loads, Then the language combo shows `python`; When the user picks `json`, Then the syntax check uses the JSON checker and `extension_for` gives `.json`.
- Given the document is empty, When the view renders, Then Save is disabled with an explanatory tooltip.
- Given the user types in the editor, When the text changes, Then `controller.set_edited_text` is called with the full editor text.
- Given a write that raises `SaveError`, When Save completes, Then an error dialog shows the OS message and the view stays usable.

## Notes for the worker
`CodeEditor`: monospace font, gutter with line numbers and one icon per issue type (distinct shapes, REQ-NFR-08), issue background colors and tooltips. Map editor lines to `render_items(document)` (DocLine or Gap per line) until the first edit; after an edit keep highlights only on lines whose text is unchanged. `ReviewView(controller, settings)`: load a `Document` from `document_changed` and `Session.edited_text` when present (edited text is the truth once set); left frame panel showing the frames (`Observation.frame_seq`) of the current line; issue counter using `issue_count`; F8 / Shift+F8 move to the next and previous issue; conflict picker as a popup listing `DocLine.alternatives`; language combo preset from `vote_language` over the frames' `language_guess` values with the user's override stored through the controller's session `language`; syntax panel from `check(text, language)` with click-to-jump; Save: confirm when `gaps > 0`, `QFileDialog.getSaveFileName` with `default_filename(language, now)`, `render_for_save(text, settings.line_ending)`, `write_file`, and an error dialog on `SaveError`. Edits call `controller.set_edited_text(text)`. Build tests with pytest-qt and a constructed `Document` (see the Models fields in `models.py`), mocking `QFileDialog` and `QMessageBox`.
