# T014: CaptureController wiring the pipeline

## Goal
When this task is done, `src/screen_copier/controller.py` provides `CaptureController(QObject)`, the one Qt-facing object that wires camera → preprocessing → session save → recognition queue → stitcher, exposing every signal and slot of the CaptureController contract so the UI tasks (T015 to T019) talk only to it and never to the camera, the API or the disk. Everything it uses is injectable, so the tests run with the fake camera, the fake recognizer and a temporary data dir.

## Acceptance criteria
- Given a controller with the fake camera, the fake recognizer on `tests/fixtures/recognizer/seq_basic/` and a temporary data dir, When 5 frames are captured, Then the last `document_changed` carries a document whose render equals `tests/fixtures/stitching/seq_basic/expected.txt`.
- Given `consent_acknowledged` is false, When a frame is captured, Then `consent_required` is emitted, the frame is saved, and the recognizer is not called until `acknowledge_consent()` is called, after which it is.
- Given each captured frame, When the recognizer is called for it, Then that frame's JPEG already exists on disk under the session's `frames/` folder.
- Given a recognizer result containing a line with `cut_off_right = true`, When it is stitched, Then `warning("cut_off", <message>, True)` is emitted.
- Given the frames of the `seq_bridge` fixture replayed through the fake recognizer, When frame 3 is stitched, Then `warning("gap", <message>, True)` is emitted; When frame 4 bridges the gap, Then `warning("gap", <message>, False)` is emitted.
- Given 3 recognized frames, When `discard_frame(2)` is called, Then the frame is marked `discarded`, the queue is told to discard it, and `document_changed` carries the render of frames 1 and 3 only.
- Given a stored session with one frame in state `queued`, When `resume_session(id)` is called, Then the frame is submitted and recognized, and `document_changed` reflects it.
- Given `lock_region(quad)` was called, When a frame is captured, Then `process` receives that quad as `locked_quad`.
- Given a captured frame with `FrameQuality.blurry = true`, When it is added, Then `frame_added` carries `quality.blurry = True` and `warning("blurry", <message>, True)` is emitted.
- Given `set_edited_text("x")` is called, When 2 s pass on the injected clock, Then the session is saved once with `edited_text = "x"`.
- Given each `document_changed` emission, When its stats are read, Then `frames`, `lines`, `gaps`, `issues`, `input_tokens` and `output_tokens` match the session and document.

## Notes for the worker
Read the public APIs of the modules you wire as code, not only as contracts: `preprocess/warp.py` (`process(frame, locked_quad, max_edge) -> ProcessResult`), `recognition/base.py` and `recognition/fake.py` (`FakeRecognizer(directory)`), `recognition/queue.py`, `session/store.py`, `stitching/stitcher.py` (`Stitcher(settings)`, `add`, `document`, `render`, `issue_count`), `camera/source.py` and `models.py`. On `capture_requested(frame, quality)`: run `process` in a `QThreadPool` worker, then allocate `seq`, save the frame JPEG with `save_frame_image`, save the session, emit `frame_added`, and submit to the queue unless consent is pending, in which case emit `consent_required` once and hold the frame (submit held frames in `acknowledge_consent()`, which also persists `consent_acknowledged = true`). On `result_ready(seq, result)`: set the frame `recognized` with its result, call `stitcher.add`, translate events into warnings (`gap` active while the document has an `overlap` gap; `ambiguous_overlap`, `cut_off` and `word_wrap` raised on their events and cleared when a later frame no longer shows the condition), emit `document_changed` with stats, save. `frame_status` updates the frame and emits `frame_updated`; `usage` accumulates into `Session.usage`; `offline_changed` mirrors into the `offline` warning; the worker's `hint` into `never_settles` and `low_resolution`; `blurry` clears after 3 s on the injected clock. Discard: `queue.discard`, mark `discarded`, rebuild the stitcher from the remaining recognized frames in seq order, save. `set_edited_text` saves after a 2 s debounce. `new_session()` creates a session and a fresh stitcher; `resume_session(id)` loads, calls `prepare_resume`, rebuilds the document from recognized frames and resubmits `queued` frames. Inject the camera worker factory, recognizer, store, settings and clock through the constructor. Tests use pytest-qt and `tmp_path`. Background: [architecture.md §2](../../../docs/architecture.md#2-components--data-flow), [§4](../../../docs/architecture.md#4-threading-model), [§12](../../../docs/architecture.md#12-controller-contract-controllerpy--code). Once merged, `controller.py` is the source of truth for this contract; update the CaptureController section and architecture §12 if a name differs.
